# Documentation language

Soma technical documentation follows the principles of ASD-STE100 Simplified
Technical English, Issue 9.

This repository policy does not replace the official standard. Use the
[official ASD-STE100 website](https://www.asd-ste100.org/) for the complete rules and
controlled dictionary.

## Vocabulary

- Use American English spelling.
- Use one term for one concept.
- Use an approved general word when it keeps the correct meaning.
- Treat code identifiers, product names, API names, and domain terms as technical
  nouns.
- Define an abbreviation at its first use.
- Do not use slang, idioms, or promotional language.

## Sentences

- Use active voice when the actor is known.
- Use simple verb forms.
- Use one topic in each sentence.
- Use no more than 25 words in a descriptive sentence.
- Use no more than 20 words in an instruction.
- Write one instruction in each sentence.
- Use `must` for a requirement.
- Do not use contractions.
- Do not use semicolons.

## Structure

- Give general information before detailed information.
- Use one topic in each paragraph.
- Use no more than six sentences in a paragraph.
- Use a vertical list for complex information.
- Use headings that identify the content.
- Keep multi-word nouns short when a fixed technical term is not necessary.

## Software exceptions

Do not change these items to satisfy a language rule:

- source code
- command names
- file paths
- schema fields
- protocol values
- quoted interface labels
- third-party product names

Explain an unusual technical term near its first use. Keep the same spelling in all
documents.

## Review

Before you merge a documentation change:

1. Check technical meaning against code, tests, and accepted decisions.
2. Check sentence length and active voice.
3. Remove ambiguous pronouns.
4. Remove unnecessary words.
5. Check links, commands, identifiers, and file paths.
6. Confirm that historical documents cannot look like current requirements.
